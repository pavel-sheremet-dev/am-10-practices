## Google-сервіси в n8n. Cloud і self-hosted

- **У cloud-версії n8n підключення спрощене.** У ноді чи в credential натискаєте **Sign in with Google**, обираєте акаунт, даєте дозволи — і все. Власний проєкт у Google Cloud створювати не треба.
- **У self-hosted інтерфейс авторизації лишився старий.** Там потрібно пройти повний шлях через Google Cloud Console:
  1. створити проєкт у Google Cloud Console;
  2. увімкнути потрібні API — Gmail API, Google Sheets API, Google Drive API, Google Docs API;
  3. налаштувати OAuth consent screen і додати свій акаунт у тестові користувачі;
  4. створити OAuth client ID типу Web application;
  5. скопіювати з n8n **OAuth Redirect URL** і вставити його в Authorized redirect URIs;
  6. Client ID і Client Secret вставити в credential у n8n і натиснути Sign in with Google.
- **Google-ноди мають окремі типи credentials.** Gmail, Sheets, Drive і Docs підключаються кожна своїм credential, навіть якщо акаунт один. Це нормально: у кожного сервісу свій набір дозволів.
- У конспекті Заняття 7 є **два відео** — окремо для cloud і окремо для self-hosted. Кому потрібні покрокові деталі, особливо на self-hosted, дивіться саме їх.

## Завдання. Обробка скарг клієнта

### Ситуація

«Смачно» отримує скарги на пошту. Менеджер щоразу читає лист, заносить дані в таблицю, пише вибачення, обирає компенсацію і відповідає клієнту. Цю рутину можна частково або повністю автоматизувати.

Будуємо workflow, який робить це сам: від листа до відповіді клієнту.

**Основний флоу**

1. Отримання листа
2. Визначення типу листа
3. Заповнення таблиці даними для менеджера
4. Створення документу з результатом розгляду скарги
5. Відповідь клієнту

**Що має витягти AI з листа:**

```json
{
  "is_complaint": true,
  "client_name": "Олена Ткаченко",
  "order_number": "4821",
  "issue": "Замовлення приїхало холодним і не те, що замовляли",
  "severity": "high"
}
```

`severity` — рівно одне з `"low"`, `"medium"`, `"high"`.

**Правило компенсації:** low → 10%, medium → 20%, high → 30%.

**Що будуємо:**

```
Gmail Trigger        (новий лист на пошті)
  → Basic LLM Chain  (розбір листа → JSON)
  → Code             (парсинг JSON + розрахунок компенсації)
  → IF               (це справді скарга?)
  → Google Sheets    (Append — реєстр скарг)
  → Google Drive     (Copy file — копія шаблону)
  → Google Docs      (Update — заповнити плейсхолдери)
  → Gmail            (Reply — відповідь клієнту з посиланням)
```

---

### Крок 1. Gmail Trigger

**Що зробити.**

- Створити новий workflow, назвати `complaints-handler`.
- Додати ноду **Gmail Trigger**, підключити credential.
- **Poll Time:** Every Minute. Частіше однієї хвилини виставити не можна.
- Надіслати собі тестовий лист і запустити прослуховування.
- Подивитись вихід ноди: знайти `id`, `threadId`, тему, відправника і текст листа.

**На що звернути увагу:**

- Тригер працює за принципом **polling**: n8n сам регулярно перевіряє пошту. При першому запуску він не чіпає наявні листи — тільки ті, що надійдуть після активації.
- `id` листа запам'ятайте — він знадобиться на останньому кроці, щоб відповісти саме на цей лист.
- Фільтри тригера (Sender, Subject, Label) зараз не вмикаємо: хочемо бачити всі листи й відсіювати їх розумно, через AI.

---

### Крок 2. AI: розбір листа

**Що зробити.**

- Додати **Basic LLM Chain** і підключити до неї **OpenRouter Chat Model**.
- Написати промпт, який просить модель повернути **тільки JSON** із полями `is_complaint`, `client_name`, `order_number`, `issue`, `severity`.
- Текст листа підставити в промпт через Expression із ноди Gmail Trigger.
- Виконати і подивитись, що повернулось.

**Промпт:**

```
Ти — асистент служби підтримки сервісу доставки їжі «Смачно».
Прочитай лист, який надійшов на пошту компанії, і витягни з нього дані.

Поверни ТІЛЬКИ валідний JSON. Без жодного тексту до або після. Без markdown-обгортки.

Структура:
{
  "is_complaint": ...,
  "client_name": "...",
  "order_number": "...",
  "issue": "...",
  "severity": "..."
}

Правила:
- is_complaint: true, якщо це скарга клієнта на замовлення, доставку, оплату
  або якість їжі. У всіх інших випадках — false: резюме, реклама, розсилки,
  пропозиції співпраці, звичайні питання без претензії.
- client_name: ім'я клієнта, якщо воно є в листі. Якщо немає — null.
- order_number: номер замовлення, якщо він згаданий. Якщо немає — null.
  Не вигадуй номер.
- issue: суть претензії одним реченням, максимум 15 слів.
- severity: рівно одне з "low", "medium", "high".
  низька — дрібна незручність, клієнт спокійний;
  середня — зіпсоване замовлення або відчутна затримка;
  висока — втрачені гроші, зіпсоване свято, повторна проблема, погрози піти.
- Якщо is_complaint = false, решту полів заповни null, а severity — "low".

Лист:
[текст_листа]
```

---

### Крок 3. Code: парсинг і розрахунок компенсації

**Що зробити.**

- Додати ноду **Code**
- Розібрати JSON із відповіді моделі й одразу дорахувати компенсацію. На виході мають бути всі поля від моделі плюс `compensation_percent` і `promo_code`. Наприклад:

```json
{
  "is_complaint": ...,
  "client_name": "...",
  "order_number": "...",
  "issue": "...",
  "severity": "...",
  "compensation_percent": ...,
  "promo_code": "..."
}
```

- `compensation_percent`: відсоток знижки.
- `promo_code`: промокод типу "SORRY**", де ** - це відсоток знижки.
- `promo_code` формувати на основі `severity` ("low" - 10, "medium" - 20, "high" - 30)
- Ми не знаємо JavaScript, але можемо скористувати АІ для формування Code виразу.

---

### Крок 4. IF: відсіюємо не-скарги

**Що зробити.**

- Додати ноду **IF**.
- Умова: значення `{{ $json.is_complaint }}`, тип **Boolean**, оператор **is true**.
- Гілку **true** ведемо далі. Гілку **false** лишаємо порожньою.

**На що звернути увагу:**

- Без цього кроку workflow генеруватиме документ і відповідатиме **на кожен лист** — включно зі спамом, резюме і розсилками. Це і зайві витрати, і лист-вибачення людині, яка ні на що не скаржилась.
- **IF чи Filter?** IF розгалужує workflow на дві гілки, Filter просто відсіює елементи без розгалуження. Тут теоретично вистачило б і Filter, але IF лишає місце для другої гілки — наприклад, згодом туди можна повісити окрему обробку звичайних питань.
- Зверніть увагу на **тип** умови. `is_complaint` приходить як boolean, а не як рядок `"true"` — якщо обрати String, умова не спрацює.

### Крок 5. Google Sheets: реєстр скарг

**Що зробити.**

- Створити Google-таблицю з колонками:

```
Дата | Клієнт | Email | Замовлення | Суть | Серйозність | Компенсація % | Статус
```

- Додати ноду **Google Sheets**, операція **Append**.
- Вибрати Document за URL і потрібний Sheet.
- Замапити колонки через Expressions. Email і дату беремо з ноди Gmail Trigger, решту — з ноди Code.
- У колонку **Статус** записати `новий`.

**На що звернути увагу:**

- **Append** сам знаходить перше вільне місце — не треба думати про номер рядка чи дублікати.
- Таблиця стоїть **одразу після IF, до генерації документа**. Логіка така: факт звернення треба зафіксувати незалежно від того, чи вдасться далі створити документ. Якщо Docs впаде — лід усе одно в реєстрі.
- Колонка **Статус** знадобиться в додатковій задачі.

---

### Крок 6. Google Drive Copy → Google Docs Update

**Що зробити.**

- Взяти готовий шаблон листа-вибачення — Google Doc із плейсхолдерами `{{client_name}}`, `{{order_number}}`, `{{issue}}`, `{{compensation_percent}}`, `{{promo_code}}`.
- Додати ноду **Google Drive**, операція **Copy File**:
  - **File** — ID шаблону (він у URL документа: `docs.google.com/document/d/{ID}/edit`);
  - **New name** — через Expression, наприклад `Вибачення — {{ $json.client_name }}`;
- Додати ноду **Google Docs**, операція **Update**. Для кожного плейсхолдера окремий action **Find and Replace Text**:
  - **Old text** — `{{client_name}}`
  - **New text** — Expression зі значенням із ноди Code.

**На що звернути увагу:**

- **Copy і Update завжди йдуть парою.** Спочатку робимо копію, потім заповнюємо її. Оригінал шаблону не змінюється — інакше після першого ж запуску шаблон перетворився б на лист конкретному клієнту.
- Нода Drive повертає **ID нової копії** — саме його передаємо в Docs і далі у відповідь клієнту.
- **Найчастіша помилка** — розбіжність назв. Якщо в шаблоні написано `{{client_name}}`, а в ноді ви шукаєте `{{clientName}}` або `{{ client_name }}` з пробілами — заміна тихо не спрацює, і клієнт отримає лист із фігурними дужками.

---

### Крок 7. Gmail Reply: відповідь клієнту

**Що зробити.**

- Додати ноду **Gmail**, операція **Reply to a message**.
- **Message ID** — беремо з тригера/

- **Email Type:** HTML.
- У тексті листа дати посилання на згенерований документ:

```
https://docs.google.com/document/d/{{ $('Google Drive').item.json.id }}/edit
```

- В **Options** вимкнути **Append Attribution**.
- Виконати весь workflow від початку і перевірити лист у себе в пошті.

**На що звернути увагу:**

- **Reply зберігає ланцюжок переписки** — відповідь приходить у ту саму гілку, а не окремим листом. Для цього й потрібен Message ID.
- Message ID беремо **зверненням до ноди за назвою**, а не через `$json` — між тригером і цією нодою вже п'ять кроків, і `$json` містить дані останньої з них.
- **Доступ до документа.** За замовчуванням новий файл бачите тільки ви. Клієнт за посиланням отримає «Request access». Щоб лист мав сенс, доступ треба відкрити — вручну, через налаштування папки або окремою нодою Drive. У домашньому завданні це вимога: доступ «для перегляду за посиланням».
- Альтернатива на випадок, коли автовідповідь страшно вмикати: операція **Create Draft** замість Reply. Автоматизація готує лист, а людина натискає «Надіслати». Це підхід human-in-the-loop.

### Підсумок Завдання

| Нода | Що вона тут робить |
|---|---|
| Gmail Trigger | ловить новий лист, віддає текст і `id` для відповіді |
| Basic LLM Chain | перетворює вільний текст листа на структуровані дані |
| Code | парсить JSON від моделі й рахує компенсацію за правилом |
| IF | зупиняє workflow на листах, які не є скаргами |
| Google Sheets (Append) | фіксує факт звернення в реєстрі |
| Google Drive (Copy) + Google Docs (Update) | створює копію шаблону і заповнює плейсхолдери |
| Gmail (Reply) | відповідає клієнту в тому самому ланцюжку, з посиланням |

**Головне.** Ви щойно зібрали майже те саме, що очікується в домашньому завданні: Gmail Trigger → AI → перевірка → таблиця → копія шаблону → заповнення → відповідь.

## Додатково. Google Sheets як черга

### Ситуація

У реєстрі скарг накопичились рядки зі статусом `новий`. Треба взяти ті, що позначені як серйозні, і перевести їх у статус `в роботі` — щоб менеджер бачив, чим зайнятись першим.

У основному завданні ми таблицю тільки **наповнювали**. Тут навчимось із неї **читати й оновлювати** — це друга половина роботи з Google Sheets.

**Що будуємо:**

```
Manual Trigger
  → Google Sheets (Get Rows)   [Execute Once]
  → Filter                     (Серйозність = висока)
  → Google Sheets (Update)     (за row_number → Статус = «в роботі»)
```

---

### Крок 1. Google Sheets: Get Rows

**Що зробити.**

- Новий workflow, **Manual Trigger**.
- Нода **Google Sheets**, операція **Get Rows**. Вказати ту саму таблицю і лист.
- У налаштуваннях ноди увімкнути **Execute Once**.
- Виконати і подивитись на вихід.

**На що звернути увагу:**

- Кожен рядок приходить окремим item, і в кожному є службове поле **`row_number`**. Саме воно робить можливим наступне оновлення — без нього n8n не знав би, який рядок міняти.
- **Execute Once** потрібен, коли перед нодою може виявитись масив items: без нього нода виконається стільки разів, скільки прийшло елементів, і прочитає таблицю багато разів поспіль.
- У самій ноді є базовий фільтр — але тільки на точний збіг. Складніші умови робимо далі.

---

### Крок 2. Filter

**Що зробити.**

- Додати ноду **Filter**.
- Умова: колонка `Серйозність` **equals** `висока`. Можна додати другу умову — `Статус` equals `новий` — і об'єднати їх через **AND**.
- В опціях увімкнути **Always output data**.
- Виконати і подивитись, скільки рядків лишилось.

**На що звернути увагу:**

- **Filter не розгалужує workflow** — він просто пропускає далі ті items, що підійшли. Тим і відрізняється від IF, який ми використовували в основному завданні.
- **Always output data** рятує від тихої зупинки: якщо жоден рядок не підійшов, Filter за замовчуванням нічого не поверне і виконання обірветься саме тут.
- Це **дворівнева фільтрація**: базовий відбір можна зробити в ноді Sheets, а складніші умови — у Filter. Разом вони дають те, чого не вміє жодна з них окремо.

---

### Крок 3. Google Sheets: Update

**Що зробити.**

- Додати ще одну ноду **Google Sheets**, операція **Update**.
- **Column to match on** — `row_number`.
- Значення для пошуку — `{{ $json.row_number }}`.
- У колонку `Статус` записати `в роботі`.
- Виконати і перевірити таблицю.

**На що звернути увагу:**

- Оновлюються **лише ті колонки, які ви заповнили**. Решта лишається як була — Update не перезаписує рядок цілком.
- `row_number` прийшов сюди через Filter від ноди Get Rows. Ланцюжок Get Rows → Filter → Update — стандартний патерн роботи з таблицею як із чергою.
- Таблиця в такому сценарії працює як маленька база даних: щось у неї пишемо, щось читаємо, щось позначаємо обробленим. Для невеликих автоматизацій цього цілком достатньо.
