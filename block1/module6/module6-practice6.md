## AssemblyAI. Реєстрація і ключ

**Що зробити.**

- Зареєструватись/увійти  на **assemblyai.com** — достатньо Gmail-акаунта.
- Перейти в **Account → API Keys**, створити ключ і скопіювати його.
- У n8n створити credential: **Generic Credential Type → Header Auth**.
  - **Name:** `Authorization`
  - **Value:** ваш ключ

**На що звернути увагу:**

- **Ключ передається без слова `Bearer`.** Це відрізняється від OpenRouter, де ми писали `Bearer sk-...`. AssemblyAI очікує в заголовку `Authorization` сам ключ і нічого більше. Найчастіша причина `401 Unauthorized` на цьому сервісі.
- **Модель обираємо свідомо.** Universal 3 Pro найточніша, але **не підтримує українську**. Для українського аудіо беремо **Universal 2**. Якщо транскрипт виходить схожим на набір випадкових слів — перша річ, яку варто перевірити, це модель.
- [Посилання на документацію](https://www.assemblyai.com/docs)

## Завдання. Оцінка дзвінка в підтримку

### Ситуація

У «Смачно» є телефонна лінія підтримки. Записи дзвінків накопичуються в папці на Google Drive і там лежать — послухати їх усі керівник не може, тому якість обслуговування ніхто не перевіряє.

Будуємо workflow, який бере запис, перетворює його на текст, оцінює роботу оператора і кладе результат у таблицю. Керівник відкриває таблицю і бачить, які дзвінки варто переслухати.

**Що будуємо:**

```
Manual Trigger
  → Google Drive        (Search Files and Folders — папка із записами)
  → HTTP Request POST   (/v2/transcript — відправляємо аудіо)
  → Wait                (5 секунд)
  → HTTP Request GET    (/v2/transcript/{id} — перевіряємо статус)
  → If                  (готово?)   false → назад на Wait
  → Basic LLM Chain     (оцінка розмови → JSON)
  → Google Sheets       (Append — реєстр дзвінків)
```

**Що має повернути AI:**

```json
{
  "operator_speaker": "A",
  "topic": "доставка",
  "politeness": "висока",
  "greeting": true,
  "resolved": true,
  "score": 8,
  "comment": "Оператор привітався, уточнив номер замовлення, запропонував компенсацію"
}
```

Допустимі значення:

- `topic` — рівно одне з `"замовлення"`, `"оплата"`, `"якість їжі"`, `"доставка"`, `"інше"`
- `politeness` — рівно одне з `"низька"`, `"середня"`, `"висока"`
- `greeting`, `resolved` — тільки `true` або `false`
- `score` — ціле число від 1 до 10
- `comment` — один рядок, максимум 20 слів

### Крок 1. Аудіо і публічне посилання

**Що зробити.**

- У Google Drive створити папку із записами дзвінків і покласти туди аудіофайл.
- Відкрити доступ **«Усі, хто має посилання» (Anyone with the link can view)** — на папку або на файл.
- У n8n: **Manual Trigger** → нода **Google Drive Trigger**.
- Подивитись вихід: там `id` і `name` файлу.

**На що звернути увагу:**

- **AssemblyAI не отримує файл — він отримує посилання.** Сервіс сам піде за цим URL і завантажить аудіо. Тому посилання має бути публічним: приватний файл на Drive сервіс просто не відкриє, і транскрибація завершиться статусом `error`.
- Пряме посилання на завантаження збирається за шаблоном:

```
https://drive.google.com/uc?export=download&id={{ $json.id }}
```

  Звичайне посилання з адресного рядка (`/file/d/.../view`) **не підійде** — за ним віддається HTML-сторінка перегляду, а не аудіо.

### Крок 2. Відправляємо аудіо в AssemblyAI

**Що зробити.**

- Нода **HTTP Request**:
  - **Method:** POST
  - **URL:** `https://api.assemblyai.com/v2/transcript`
  - **Authentication:** Generic → Header Auth → credential
  - **Send Body:** увімкнути; **Body Content Type:** JSON; **Specify Body:** Using JSON
  - поле з тілом перевести в режим **Expression** — інакше `{{ }}` піде в AssemblyAI як звичайний текст
- Тіло запиту:

```json
{
  "audio_url": "https://drive.google.com/uc?export=download&id={{ $json.id }}",
  "speech_models": ["universal-2"],
  "language_code": "uk",
  "speaker_labels": true,
  "speakers_expected": 2
}
```

- Виконати і подивитись відповідь: у ній `id` задачі та `status: "processing"`.

**На що звернути увагу:**

- **Тексту у відповіді немає і не буде.** POST лише ставить файл у чергу. Все, що ми отримали, — ідентифікатор задачі. Це і є асинхронний API.
- **`language_code: "uk"`** — автовизначення мови працює непогано, але якщо мова відома заздалегідь, краще вказати її явно. Менше шансів, що українську розпізнають як російську чи польську.
- **`speaker_labels: true`** вмикає розділення по спікерах. Без нього ми отримаємо суцільний текст і не зможемо відрізнити оператора від клієнта — а оцінюємо ми саме оператора. `speakers_expected: 2` підвищує точність цього розділення.
- Не плутайте два `id`: `id` файлу з Google Drive і `id` задачі транскрибації. Далі працюємо з другим.

### Крок 3. Цикл очікування: Wait → GET → If

**Що зробити.**

- Перейменувати ноду з попереднього кроку на **AssemblyAI POST** — далі ми будемо звертатись до неї за назвою.
- Нода **Wait**, режим **After Time Interval**, 5 секунд.
- Нода **HTTP Request**, перейменувати її на **AssemblyAI GET**:
  - **Method:** GET
  - **URL** — з підстановкою `id` задачі з ноди POST:

```
https://api.assemblyai.com/v2/transcript/{{ $('AssemblyAI POST').item.json.id }}
```

  - той самий Header Auth credential.
- Нода **If**. Дві умови, об'єднані через **Any (OR)**:

```
{{ $json.status }}   equals   completed
{{ $json.status }}   equals   error
```

- **Вихід `false` з'єднати назад із нодою Wait.**
- Виконати workflow цілком і подивитись, як він крутиться, поки статус не зміниться.

**На що звернути увагу:**

- **Це цикл, зібраний руками.** У n8n немає ноди «чекай, поки не буде готово» — ми будуємо її з трьох звичайних нод. Патерн універсальний: так само працює з будь-яким API, що віддає ідентифікатор задачі замість результату.
- **Wait стоїть перед GET, а не після.** Питати про статус одразу після відправки немає сенсу — відповідь завжди буде `queued`.
- **Друга умова потрібна не для краси — без неї workflow зависає.** Якщо перевіряти тільки `completed`, то при недоступному файлі статус назавжди лишиться `error`, цикл крутитиметься нескінченно і витратить ліміт виконань.
- Звертайтесь до `id` задачі **через назву ноди**, а не через `$json`.
- У відповіді зі статусом `completed` дивіться на три поля: `text` — суцільний транскрипт, `utterances` — масив реплік із мітками спікерів, `audio_duration` — тривалість у секундах.

### Крок 4. Оцінка розмови через LLM

**Що зробити.**

- Нода **Basic LLM Chain** + **OpenRouter Chat Model**.
- У промпт підставити діалог із мітками спікерів через Expression:


```
{{ $json.utterances.map(u => 'Спікер ' + u.speaker + ': ' + u.text).join('\n') }}
```

- Що може бути в промпті:
  - роль — керівник служби підтримки «Смачно», який оцінює роботу оператора;
  - пояснення, що спікери позначені літерами, і **визначити оператора треба самостійно** — за привітанням, за фразами на кшталт «чим можу допомогти»;
  - вимога повернути **тільки валідний JSON** без markdown-обгортки;
  - структура і **перелік допустимих значень** для `topic`, `politeness`, `score`;
  - вказівка не вигадувати: якщо з розмови незрозуміло, чи питання вирішене — `resolved: false`.
- Виконати і подивитись результат.

**На що звернути увагу:**

- **Перелік допустимих значень — це той самий прийом, що й на першій зустрічі.** `topic` навмисно взято з промпту першої зустрічі: реєстр дзвінків і реєстр звернень повинні мати однакові категорії, інакше їх не звести разом.
- **Транскрипт не ідеальний.** Імена, назви страв, промокоди розпізнаються фонетично і часто неправильно. Модель на наступному кроці розуміє контекст і здебільшого сама виправляє очевидне — але тільки якщо знає, про що мова. Чим більше контексту в промпті (назва компанії, типові теми звернень), тим кращий результат.
- **`speaker A` — не обов'язково оператор.** AssemblyAI просто нумерує голоси в порядку появи. Тому роль визначає модель за змістом реплік, а ми просимо її записати результат у `operator_speaker` — щоб потім можна було перевірити, чи не помилилась.
- Оцінка від моделі — **не абсолютна істина**, а сигнал. Її призначення — підказати керівнику, які 5 дзвінків із 200 варто переслухати самому.

### Крок 5. Реєстр дзвінків у Google Sheets

**Що зробити.**

- Створити Google-таблицю з колонками:

```
Дата | Файл | Тривалість, с | Тема | Ввічливість | Привітався | Питання вирішене | Оцінка | Коментар
```

- Нода **Google Sheets**, операція **Append**.
- Замапити колонки:
  - `Дата` — `{{ $now.format('yyyy-MM-dd HH:mm') }}`;
  - `Файл` — `name` з ноди Google Drive;
  - `Тривалість, с` — `{{ $('AssemblyAI GET').item.json.audio_duration }}`;
  - решта — з відповіді моделі.
- Модель повертає JSON **рядком**, тому поля дістаємо одним із двох способів:
  - Expression на кожне поле: `{{ JSON.parse($json.text).score }}`
  - або нода **Code** перед Sheets — як робили на минулій зустрічі.
  - або використати `Structured Putput Data`
- Виконати workflow від початку до кінця і перевірити таблицю.

**На що звернути увагу:**

- **Що зробити з цим далі.** Оцінка нижче 5 — привід для окремої ноди: сповіщення керівнику в Telegram або окрема вкладка «на розбір». Зараз нам вистачає таблиці.
- **Ланцюг цілком:** аудіо → транскрибація → постобробка LLM → збереження. Сама по собі транскрибація дає мало — цінність з'являється саме на етапі обробки.
- Так само обробляються голосові повідомлення з Telegram, записи нарад, дзвінки менеджерів з продажу. Змінюється джерело аудіо і промпт оцінки, решта конструкції — та сама.

### Підсумок Завдання

| Нода | Що вона тут робить |
|---|---|
| Google Drive (Search Files) | дає `id` файлу для збирання публічного посилання |
| HTTP Request POST | ставить аудіо в чергу, повертає `id` задачі |
| Wait | пауза між перевірками, щоб не перевищити ліміти API |
| HTTP Request GET | питає статус задачі |
| If (+ зворотний зв'язок на Wait) | цикл очікування, зібраний руками |
| Basic LLM Chain | перетворює транскрипт на структуровану оцінку |
| Google Sheets (Append) | реєстр дзвінків для керівника |
