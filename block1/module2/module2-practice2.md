## OpenRouter. Реєстрація та API-ключ

Реєструємось разом на зустрічі. Акаунт і ключ знадобляться і для Завдання 2, і для домашнього завдання.

**Що можна зробити зробити.**

1. **openrouter.ai** → Sign up / Sign in. Найшвидше через Google-акаунт.
2. **Models** → сортування **Pricing: Low to High**. Безкоштовні моделі опиняться зверху: у назві позначка `:free`, ціна input і output — $0.
3. Відкрити картку однієї моделі. На що дивитись:
   - **назва-ідентифікатор** — саме її ми підставимо в запит;
   - **кількість параметрів (B)** — може бути не вказана; від 120B модель поводиться помітно стабільніше.
4. **Personal Settings → API Keys → Create key**, дати назву.
5. **Скопіювати ключ одразу** — він показується лише один раз. Зберегти в надійному місці.

**Про що пам'ятати.**

- **Ключ — це пароль.** Не в скріншот, не в Google Docs, не в публічний репозиторій. Якщо ключ засвітився — видалити його через Delete і створити новий. Це нормальна процедура, а не аварія.
- **Ліміти безкоштовних моделей:** 20 запитів на хвилину; 50 на день, якщо на балансі менше 10 кредитів. Для зустрічі і для ДЗ цього вистачає з запасом.

## Завдання 1. Токени: оцінка промпту

### Ситуація

Той самий сервіс доставки «Смачно», той самий промпт, ті самі 300 звернень на день.

**Інструмент:** https://platform.openai.com/tokenizer

---

### Крок 1. Виміряти наш промпт

**Що зробити.**

- Вставити у токенайзер фінальний промпт із першої зустрічі — той, що з роллю, схемою, допустимими значеннями і прикладами.
- Подивитись на кількість токенів.
- Перемкнути внизу режим **Text → Token IDs** і назад, щоб побачити кольорову розбивку.

**На що звернути увагу:**

- Токенів в українському тексті більше, ніж здається на око. На кольоровій розбивці видно чому: англійські слова часто вкладаються в один токен, українські рвуться на шматки по два-три символи.
- Пробіли й розділові знаки — теж токени.
- Приклади Few-Shot — це відчутна частина промпту. На минулій зустрічі ми казали «приклади не безкоштовні» і «більше не завжди краще». Ось конкретна цифра, яка за цим стоїть.
- Головне: **цей промпт іде на кожному виклику.** Не один раз, а 300 разів на день. Модель не пам'ятає його з минулого разу.
- Звернення клієнта, яке підставляється в плейсхолдер, — це ще токени зверху.

> Токенайзер показує розбивку моделей OpenAI. Модель, яку ви візьмете на OpenRouter, може рахувати трохи інакше. Порядок величини від цього не змінюється — ми міряємо не точну ціну, а співвідношення.

---

### Крок 2. Спробувати оптимізацію

**Що зробити.**

- Переписати службову частину промпту англійською — роль, інструкції, назви полів.
- Український текст лишити тільки там, де його читає людина.
- Переміряти в токенайзері й порівняти з Кроком 1.

**На що звернути увагу:**

- Назви полів у нашому JSON (`topic`, `priority`, `needs_human`, `summary`) англійською **не випадково**. Це рішення, а не звичка.
- Але межу треба тримати: `summary`, який читатиме український менеджер, і відповіді клієнтам лишаються українською. Економія не має коштувати якості там, де текст бачить людина.

---

### Підсумок. Для чого нам це знати

1. **Модель не бачить букв і слів.** Вона бачить токени. Усе інше випливає звідси.
2. **Токени — це гроші.** Промпт для автоматизації це не текст, а стаття витрат, помножена на кількість викликів.
3. **Українська дорожча за англійську.** Це не привід відмовлятись від української — це привід знати, де вона справді потрібна, а де ні.
4. **Промпт-інжиніринг — це в тому числі компроміс** між «наскільки детально пояснити» і «скільки це коштує».

## Завдання 2. Перший запит до моделі через API

**Мета.** Отримати базове уявлення про API і HTTP та зробити перший робочий запит до моделі своїми руками.

**Ситуація.** Той самий промпт. Тільки тепер без ChatGPT — напряму до моделі.

---

### Анатомія запиту

Аналогія: HTTP-запит — це лист.

**Запит:**

| Частина | Що це | У нашому випадку |
|---|---|---|
| Метод | що ми хочемо зробити | `POST` — надіслати дані і отримати результат |
| URL | куди звертаємось | адреса OpenRouter |
| Заголовки | службове: хто я, у якому форматі шлю | ключ і `Content-Type` |
| Тіло | власне вміст | JSON з назвою моделі і повідомленням |

**Відповідь:**

| Частина | Що це |
|---|---|
| Статус-код | `200` — успішно, `401` — не пустили, `429` — забагато запитів, `500` — поламалось на боці сервера |
| Тіло | дані у форматі JSON |

Питання, над яким варто на секунду зупинитись: коли ви просто відкриваєте сайт у браузері — це який метод? Це `GET`. І це теж HTTP-запит, просто його робить за вас браузер.

---

### Крок 1. Обрати модель

**Що зробити.**

- Повернутись до списку безкоштовних моделей в OpenRouter.
- Скопіювати **повний ідентифікатор** моделі — разом із назвою провайдера і суфіксом `:free`.

---

### Крок 2. Зібрати запит у ReqBin

**Що зробити** на **reqbin.com**:

- **Метод:** `POST`
- **URL:**

```
https://openrouter.ai/api/v1/chat/completions
```

- **Заголовки:**

```
Authorization: Bearer ваш_ключ
Content-Type: application/json
```

- **Тіло** (вкладка Body, формат JSON):

```json
{
  "model": "назва_безкоштовної_моделі",
  "messages": [
    { "role": "user", "content": "Що таке LLM? Відповідай коротко, 2-3 речення." }
  ]
}
```

**На що звернути увагу:**

- `Bearer` означає «пред'явник»: хто має ключ, той і має доступ. Звідси й правило не світити ключ.
- `messages` — це **масив об'єктів**. Не один рядок, а список. Так само влаштована історія розмови: кожне повідомлення — окремий об'єкт із `role` і `content`. Саме це ChatGPT непомітно робить за вас у чаті.
- Якщо JSON не приймається — перевірте коми і лапки. Допоможе будь-який онлайн JSON-валідатор.

---

### Крок 3. Send і прочитати відповідь

**Що зробити.**

- Натиснути **Send**.
- Знайти статус `200 OK`.
- У відповіді знайти текст моделі.

Шлях до тексту:

```
choices[0].message.content
```

**Розберемо шлях по частинах:**

- `choices` — масив варіантів відповіді. Модель у принципі може повернути кілька, тому це список.
- `[0]` — перший елемент. Нумерація з нуля.
- `message` — об'єкт із повідомленням.
- `content` — сам текст.

Це та сама вкладеність, про яку йшлося в конспекті. Вміння прочитати такий шлях — базова навичка на весь курс: у n8n ви робитимете рівно те саме.

---

### Крок 4. Подивитись на `usage`

**Що зробити.** Прокрутити відповідь нижче і знайти об'єкт `usage`. Там будуть приблизно такі поля:

```json
"usage": {
  "prompt_tokens": 0,
  "completion_tokens": 0,
  "total_tokens": 0
}
```

**На що звернути увагу:**

- `prompt_tokens` — це те саме, що ми щойно міряли в токенайзері вручну. Тільки тепер його порахував сам провайдер, точно і за фактом.
- `completion_tokens` — відповідь моделі. Ті самі токени, які коштують у 2–3 рази дорожче.
- Ось тут два сьогоднішні завдання змикаються: **Завдання 1 пояснює, чому ці числа важливі, а Завдання 2 показує, звідки їх брати.**

---

### Крок 5. Зламати навмисно

Робимо це свідомо, щоб навчитись читати помилки. Поведінка тут детермінована — відтворюється завжди.

**Що зробити.**

1. Прибрати слово `Bearer` із заголовка, лишити просто ключ → **401**. Сервер не зрозумів схему автентифікації.
2. Повернути `Bearer`, зіпсувати назву моделі на неіснуючу → помилка з описом у тілі відповіді.
3. Прибрати кому в JSON → скарга на некоректний JSON.

**На що звернути увагу:**

- Помилка — це не «щось зламалось», а повідомлення з конкретною причиною. Читаємо статус, потім тіло відповіді.
- `401` — це майже завжди ключ або формат заголовка. `429` — ліміт, треба зачекати. `500` — не ваша провина, повторіть пізніше.
- Ці три хвилини заощадять вам години на домашньому завданні.

---

### Крок 6. Наш промпт через API

**Що зробити.** Підставити в поле `content` промпт із першої зустрічі й отримати ту саму JSON-класифікацію, але вже через HTTP-запит.

```json
{
  "model": "назва_безкоштовної_моделі",
  "messages": [
    {
      "role": "user",
      "content": "Промпт + Звернення"
    }
  ]
}
```

**На що звернути увагу:**

- Промпт **не можна просто вставити в JSON як є.** Він багаторядковий і містить лапки, а JSON цього всередині рядка не дозволяє.
- Тому переноси рядків записуються як `\n`, а лапки всередині — як `\"`. Це називається **екранування**.
- Робити це руками не треба: вставте промпт у будь-який JSON-екранувальник (наприклад https://maytapi.com/tools/json-escaper-unascaper) або попросіть модель перевести текст у валідний JSON-рядок. У другому випадку результат варто перевірити — модель може помилитись.
- У n8n ця проблема зникне: там промпт вводиться в поле, а екранування робить сам інструмент. Але знати, що відбувається під капотом, треба саме зараз — бо складається HTTP-запит, тіло якого має бути валідним JSON.

**Що ви побачите:** у відповіді приходить чистий JSON із класифікацією — той самий результат, що й у ChatGPT. Різниця в тому, що тепер це **машинний виклик**, який можна поставити в автоматизацію.

### Підсумок Завдання 2

| Що зробили | Що з цього забираємо |
|---|---|
| Зібрали POST-запит із чотирьох частин | будь-який API влаштований так само: метод, URL, заголовки, тіло |
| Передали ключ через `Authorization: Bearer` | стандартна схема для більшості сервісів, не тільки OpenRouter |
| Прочитали `choices[0].message.content` | навичка читати вкладений JSON — знадобиться на кожному занятті далі |
| Подивились на `usage` | вартість виклику видно за фактом, а не на око |
| Навмисно отримали 401 | помилка це повідомлення з причиною, а не глухий кут |

**Головне.** Ви щойно зробили руками те, що далі за вас робитиме n8n. Коли на наступному модулі ви підключите модель у workflow і воно «просто запрацює» — ви знатимете, що саме там відбувається: формується HTTP-запит, у ньому JSON із промптом, назад приходить JSON із відповіддю.

## Додатково. Gemini API — інший провайдер

Беремо, якщо лишиться час. Якщо не встигнемо на зустрічі — це хороша вправа, щоб зробити її самостійно.

**Мета** — побачити, що **єдиного стандарту немає**, і що OpenRouter вирішує це лише в межах того, що він покриває.

**З чого почати.** Безкоштовно використати моделі Gemini через OpenRouter не вийде. Хочете їх безкоштовно — йдіть напряму до провайдера. Це і є причина, чому автоматизатору доводиться поступово розбиратися з API різних провайдерів, а не вивчити один раз і назавжди.

**Що зробити.**

1. **aistudio.google.com** → увійти Google-акаунтом → **Get API key** → створити ключ. Безкоштовний рівень доступний без прив'язки картки, зі своїми лімітами.
2. Зібрати запит у ReqBin чи іншому HTTP-клієнті на основі даних із документації (https://ai.google.dev/gemini-api/docs/get-started#rest):

```
curl -X POST "https://generativelanguage.googleapis.com/v1beta/interactions" \
  -H "x-goog-api-key: $GEMINI_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "gemini-3.8-flash",
    "input": "Explain how AI works in a few words"
  }'
```

Де:

- **Метод:** `POST`
- **URL**: https://generativelanguage.googleapis.com/v1beta/interactions
- **Заголовки:**
  ```
  x-goog-api-key: ваш_ключ
  Content-Type: application/json
  ```
- `-d` - тіло запиту
  ```json
  {
    "model": "gemini-3.5-flash-lite",
    "input": "Що таке LLM? Відповідай коротко, 2-3 речення."
  }
  ``` 

**Висновок:**

- Задача одна й та сама — «надішли текст, отримай відповідь». А от **як саме** це записується, вирішує кожен провайдер сам.
- OpenRouter цінний саме тим, що ховає ці відмінності: змінили назву моделі в тілі — і працюєте з іншим провайдером, нічого не переписуючи.
- Але щойно потрібне щось поза його межами — безкоштовний Gemini, специфічна можливість, свій корпоративний сервіс — доводиться відкривати документацію провайдера і збирати запит під нього.
- **Навичка, яка залишається:** будь-який API читається однаково. Знайти в документації метод, URL, спосіб автентифікації, форму тіла і шлях до потрібного поля у відповіді. Далі — деталі.

Актуальні URL, назви моделей і ліміти — у документації: https://ai.google.dev/gemini-api/docs
